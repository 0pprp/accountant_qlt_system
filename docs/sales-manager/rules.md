## 1. التبويبات — كل طلب في تبويب واحد

المصدر (REPO:405-445) يجعل التبويبات متداخلة: «غير المسند» و«المرسلة» يتقاطعان، و«الكل» لا يساوي المجموع، والمحجوز باستثناء يختفي من الكل. الجديد يحسب تبويب كل طلب بقاعدة واحدة (`SalesRequestAdminQuery.TabKeyFor` و`TabQuery`):

| الترتيب | الشرط | التبويب |
|---|---|---|
| 1 | محذوف | المحذوفة (عدا المبيع الممسوح، فيظهر للأدمن فقط في «حذوفات المبيعات») |
| 2 | LegalFollowup | القانونية (والقضية المكتملة تظهر بشارة «تمت المتابعة» من `LegalCaseStatus`) |
| 3 | Completed | تم البيع |

| 5 | حجز استثناء حيّ (Pending أو Rejected، أو Approved لم يُستهلك) | الاستثناءات (يظهر للطالب والمقرر) |
| 6 | New، أو بلا موظف | غير المسند |

| 8 | PreparedForSale / InProgress / ConvertedToSale | جاهز للبيع |

- **«الكل»:** مجموع التبويبات 2–10 المسموحة للمستخدم.
- **«المرسلة»:** حُذفت، وصار المصدر فلتراً (`sourceType`).

## 3. حذف المبيع نهائياً — ماذا يحدث

ينفَّذ في معاملة واحدة، بالترتيب:
1. **المخزون:** كل مادة لها `ProductId` ترجع كميتها: `Product.RemainingCount += Quantity`. هذه نفس المواد التي نقصت عند الاعتماد.
2. **نقد البائع:** مجموع تسديدات الطلب يُخصم من `UndeliveredCashAmount` للبائع، بنفس منطق حذف التسديد الموجود.
3. **القاصة:** شراء المنتجات الخارجية (`Purchase`) يُحذف، ويُرجع مبلغه للقاصة الفرعية بحركة `Refund` عبر `ISafeLedger` (لا حذف حركات).
4. **الأرشيف:** سجلات `ArchiveTransaction` وأحداثها تُحذف، بقرار المالك: «مسح كل شيء».
5. **المهام:** المهام الإدارية المرتبطة بالمبيع تُفك عنه.
6. **الحذف:** التسديدات والطلب (Order) تُحذف، ومعها المواد والمرفقات بالـ cascade.
7. **طلب البيع:** يبقى محذوفاً (Completed + IsDeleted، بلا `LinkedOrderId`) مع السبب ومن حذف ومتى. لا يظهر في «المحذوفة» ولا يُسترجع (`SoldSaleWiped`).
8. **سجل النشاط:** يُكتب ملخص JSON فيه الزبون والتاريخ والسعر والمقدمة والواصل وعدد التسديدات والمواد والسبب، ويعرضه تبويب «حذوفات المبيعات».

- **قبل التنفيذ:** يرى المستخدم معاينة الأثر (`GET {id}/delete-sold-impact`).
- **التأكيد:** إذا وُجدت تسديدات، يجب تأكيدها بمربع اختيار.

## 4. الباقي — قاعدة واحدة للنظام

مطابق لـ`View_CustomersRemaining` في المصدر (`docs/najaf-transfer/BALANCE_FORMULA.md`):

- **باقي الزبون:** مجموع `SellAmount` لمبيعاته المعتمدة − كل تسديداته، مقرّباً لأقرب 1000.
- **احتساب كل تسديد مرة واحدة:**
  - التسديد المربوط بمبيع يُحسب لزبون المبيع، وفي فرع المبيع.
  - التسديد غير المربوط (`OrderId = null`) يُحسب لزبونه (`CustomerId`)، وفي فرع الزبون.
- **إجمالي الفرع / القائمة:** مجموع باقي الزبائن المقرّب، **بما فيه الدائن** (الباقي السالب)، والزبائن الذين لهم تسديد بلا مبيع.
- **مكان القاعدة:** `Application/Common/Balances/CustomerBalanceQuery.cs` (`CustomerBalanceRules`).
- **الشاشات التي تستعملها الآن:**
  - المبيعات المنجزة: إجمالي الباقي والواصل.
  - متابعة المبيعات: باقي الزبون مع غير المخصص، وإجمالي القائمة مقرّب.
  - متابعة المندوبين: غير المخصص يدخل في تسديد الزبون.
  - تقييمات الإدارة.
  - عمل المتابعين: عبر `FollowerFactsQuery`.
- **شاشات وتطبيقات أخرى تستعمل القاعدة (تحويل ثانٍ):**
  - موظفو المبيعات (البطاقات والتقييم).
  - تقييمات تطبيق المبيعات.
  - دفتر التحصيل والملف المالي في تطبيق المندوب.
  - بطاقات قوائم تطبيق المتابع، والمتدنية (عبر `FollowerFactsQuery`).
  - زبائن الفرع، وبحث Excel: صار يظهر الدائن بالسالب بدل صفر، والمعتمد فقط.
  - الأسماء القانونية، وأهلية قرار المتأخر.
  - بروفايل التدقيق، والمطابقة.
- **تبقى على مستوى المبيع (لا تتغير):** أعمدة الطلبات، وملخص المبيع، وخريطة المبيعات، وحسابات بروفايل التدقيق، والتنازلات. تعرض باقي المبيع الواحد بالتصميم.
