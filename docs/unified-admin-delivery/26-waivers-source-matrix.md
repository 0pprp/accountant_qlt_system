# 26 — مصفوفة مصدر التنازلات

## تعريف المجال (من المصدر)
«طلب التنازل» و«التنازل» مرحلتان لنفس المجال وليستا كيانين منفصلين:
- `طلب تنازل` = بعد موافقة المفوض وقبل تطبيق المحاسب (`AwaitingAccountant` + قرار فرع).
- `تنازل` = بعد تطبيق المحاسب لخصم سعر البيع.

دورة البوابة: `Pending → Rejected` أو `Pending → AwaitingAccountant → Approved`.

مرجع استكشاف: [استكشاف التنازلات](6716663d-4144-433d-953a-82d7006fd2b5).

## الفاعلون
| الطرف | الإجراء |
|---|---|
| مدير الفرع | إنشاء طلب (ملاحظة إلزامية ≤2000) + متابعة تاريخه |
| المدير المفوض | قائمة/تفاصيل؛ قبول بمبلغ >0 أو رفض |
| المحاسب الرئيسي | تطبيق الخصم فقط (لا رفض في المسار النشط) |
| المدير/المراقب | قراءة فقط |

## انتقالات
| الحالة | الإجراء | الفاعل | الشروط | الجديدة | الآثار |
|---|---|---|---|---|---|
| — | Create | فرع | ملاحظة | Pending | طلب + تدقيق |
| Pending | Reject | مفوض | — | Rejected | قرار؛ بلا أثر مالي |
| Pending | Approve | مفوض | مبلغ >0 | AwaitingAccountant | صف `طلب تنازل` في سجل القرارات + طابور محاسب |
| AwaitingAccountant | Apply | محاسب | سقف المتبقي | Approved | خفض SellAmount؛ صف `تنازل`؛ idempotency |

## الأثر المالي المثبت
خصم من إجمالي البيع (`SellAmount`) بحد `min(requested, saleTotal−paid)` — **ليس** تسديد قسط ولا حذف سجل.
المسار القديم `waivers/apply` (دفع) معلّم legacy ولا يُنقل.

## سياسة التكرار
- لا يمنع المصدر طلبات Pending متعددة لنفس الزبون.
- تطبيق مالي مرة واحدة لكل طلب (مفتاح idempotency).
