# 07 — مصفوفة قواعد المتدنية

إثبات مصدر: `DirectorFollowerOpsDeclineRules` + `GetDecliningAsync` + تبويب `declining` في `director-follower-work.vue` + `FollowerDeclineRules` / `FollowerDeclineService` في تطبيق المتابع.

## الخلاصة

| سؤال | الجواب المثبت |
|---|---|
| وحدة السجل | **زبون** (`CustomerId`) ضمن قوائم التكليف الحالي |
| التعريف | هبوط **درجتين** (−10 نقاط) خلال **7 أيام** على انتقال محدد فقط |
| الانتقالات المسموحة | ممتاز→ضعيف · جيد→متلكئ · ضعيف→سيء |
| هل كل باقي = متدني؟ | **لا** |
| هل فئة ضعيف العامة = المتدنية؟ | **لا** |
| الفترة | Lookback = 7 أيام بين لقطتي تقييم (`CaptureDate`) |
| المقارنة | لقطة حالية مقابل أحدث لقطة سابقة ضمن النافذة |
| هل تاريخ سابق تقديري من بيانات اليوم؟ | لقطة **اليوم** تُحسب حيًا من الوقائع الحالية وتُخزَّن. الأيام السابقة **لقطات مخزّنة فقط** — لا نولّد تاريخًا وهميًا |
| كتابة من اللوحة؟ | **لا** — القسم قراءة فقط للمدير/المراقب |

## قواعد تفصيلية

### R1 — الشمول في مجموعة اللقطة اليومية

| | |
|---|---|
| الدليل | `FollowerDeclineService.RefreshForFollowerAsync` + مجموعة `ActiveCustomerRules` بالجديد |
| الشرط | رصيد مفتوح (`AmountRemaining > 0`) + آخر تسديد خلال 30 يومًا من asOf بغداد |
| التقييم | `CustomerRatingCalculator.ScoreFor(..., usePhantomSaleDate: true)` |
| مثال | زبون عليه باقي وآخر دفعة منذ 10 أيام → يُلتقط اليوم |
| مقابل الجديد | `FollowerDecliningDataService.CaptureTodaySnapshotsAsync` |

حد 40 يومًا لنشاط القائمة **لا يُطبَّق** هنا (غير مثبت بالمصدر لهذا القسم).

### R2 — تعريف المتدني

| | |
|---|---|
| الدليل | `DirectorFollowerOpsDeclineRules.IsDeclining` |
| الشرط | `0 ≤ daysBetween ≤ 7` وانتقال هدف و`fromScore - toScore ≥ 10` |
| مثال مدخلات | ممتاز/10 → ضعيف/0 خلال 5 أيام → **متدني** |
| مثال مرفوض | ممتاز→جيد خلال 3 أيام → ليس متدنيًا؛ ممتاز→ضعيف خلال 8 أيام → خارج النافذة |
| مقابل الجديد | `FollowerDeclineRules` |

### R3 — القانونية / المصفر / المؤرشف

| حالة | السلوك المثبت |
|---|---|
| مصفر (باقي 0) | خارج مجموعة اللقطة → لا يظهر |
| قانوني (`IsLegal`) | لا استثناء صريح في قواعد المتدنية؛ يدخل إن انطبقت R1 ثم R2 |
| دفعات ملغاة/معكوسة | تعتمد على ما يُجمَع في `InstallmentPayments`؛ لا منطق إلغاء منفصل في مصدر المتدنية |

### R4 — التكليف ونقل القائمة

| | |
|---|---|
| النطاق | قوائم `OrderList.MotabaId = followerId` ضمن الفروع المسموحة |
| بعد النقل | العرض يتبع **التكامل الحالي**؛ لا يُنسب عمل متابع سابق باسم الحالي |
| لقطات قديمة | تبقى على CustomerId؛ تظهر إن بقيت القائمة ضمن نطاق المتابع المعروض |

### R5 — الملاحظات ومصادقة البيع

| حقل | المصدر | الجديد |
|---|---|---|
| HasNote | أحدث ملاحظة زبون | `null` + `notesAvailability=not_implemented` حتى دفعة08 — ليس «لا» |
| HasSaleAuth | وجود مصادقة على الزبون لقوائم المتابع | من `FollowerSaleAuthentications` على قوائم النطاق |

## ما ليس متدنية

- مسار Committee القديم سابقًا (أيام تسديد فائتة) — **أُصلِح** ليطابق قواعد اللقطات.
- بطاقات فئة «ضعيف» في التقييمات العامة (دفعة04).
- عدادات الباقي في مصادقة البيع (دفعة06).
