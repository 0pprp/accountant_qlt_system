| تطبيقات الموبايل الميدانية | خارج التركيز ما لم يؤثر API على شاشة إدارية | لم تُلمَس |

## ما أُصلح في هذه الجولة

1. **خطوط وUI عام** (دفعة سابقة + تحقق): ElMessiri عبر التوكنات/`qalaat-ui`، ووراثة `font-family: inherit` على الشاشات الإدارية.
2. **WaiversPage**: تحقق مبلغ الموافقة، تحقق إنشاء الطلب، تأكيد تطبيق الخصم، ترقيم صفحات عند تجاوز `pageSize`.
3. **RequestCard / RequestFilters / SalesRequests query**: عرض حالة الاستثناء + فلتر معلّق/موافق/مرفوض مربوط بـ API.
4. **DelegateSettingsPage**: تأكيد تسجيل الخروج + بيانات جلسة أوضح.

## جولة السيناريوهات على الدومين

حساب إداري قائم (بدون إنشاء مستخدمين). التحقق عبر الواجهة + API الإنتاج:

| سيناريو | متوقع (مرجع/عقد) | فعلي | ملاحظة |
|---|---|---|---|
| تنازلات إشراف | قائمة + فلاتر حالة + عدّادات قيد المفوض/بانتظار المحاسب | صفحة تعمل؛ العدّادات 0؛ «لا طلبات» | لا بيانات تنازل حالية على الإنتاج |
| استثناءات المفوض | قائمة + حالة + قرار | طلب #1 ظاهر؛ حالة «بانتظار قرار المفوض»؛ فلتر «حالة الاستثناء» ظاهر | مطابق لعقد الاستثناء الحالي |
| ملخص/تقييمات الإشراف | شاشات supervision | تُفتح بعناوين وفلاتر App* | سلوك المصفوفة يعتمد على الفروع/الشهر |
| مبيعات خاطئة مفوض | صندوق ≤6 | شاشة تعمل مع نص الدور | |
| حسابات مدراء فرع | إنشاء/تعطيل ضمن النطاق | شاشة تعمل | |
| إعدادات مفوض | جلسة + خروج مؤكد | نص الهوية + confirm جاهز في البناء المنشور | |
| مهام فرع مسندة | مسار assigned-tasks | الانتقال قد يهبط إلى مساحة الزيارات حسب الصلاحية/التبويب الافتراضي | سلوك مسار/صلاحية؛ ليس كسر UI عام |
| محاسب رئيسي — تطبيق تنازل | Apply على AwaitingAccountant | مسار الواجهة جاهز؛ لا صفوف للاختبار الحي | يحتاج بيانات |
| نسخة احتياطي DB | موجودة في المرجع | غير موجودة في اللوحة | فجوة مقصودة/محجوبة |

أدوار مدير مبيعات / مراقب / مدير فرع: المسارات من `PAGE_MAP` متاحة عبر قوائم «المبيعات / لوحة الإدارة / إدارة الفروع» لنفس الحساب الشامل؛ الفروقات الظاهرة كانت UI/فلاتر أكثر من اختلاف دورة قرار مثبتة على بيانات فارغة.
