# 16/17 — هوية موظف المبيعات (حسم مشترك)

## المشكلة
في النظام القديم: `UserType = موظف مبيعات` ≠ `مندوب` ≠ `متابع`.  
في الجديد: دور `Mandob` (المندوب) استُخدم لكل من ملكية قوائم الجباية وتطبيق المبيعات — وهذا ليس إثبات أهلية كافياً.

## القرار
**أهلية موظف المبيعات** = تكليف صريح `SalesEmployeeAssignment` نشط:

| الحقل | المعنى |
|---|---|
| UserId | الحساب |
| BranchId | فرع التكليف (ليس مجرد UserBranch) |
| StartsAtUtc | بداية الأهلية |
| EndsAtUtc | null = ساري؛ وإلا انتهى |
| CreatedByUserId | من ثبّت التكليف |

### قواعد
1. **ليس** إثباتًا وحيدًا: `role=Mandob`، وجود بيع سابق، GPS، أو آخر Login.
2. **مندوب الجباية**: دور Mandob + `OrderList.MandobId` — بلا تكليف مبيعات لا يظهر في Overview/Employees/Followup directory/تتبع المبيعات.
3. **الوظيفتان معًا**: مسموح — Mandob للجباية + Assignment للمبيعات؛ كل مسار يتحقق من أهليته.
4. **Motaba**: متابع فقط؛ لا يُدرَج كموظف مبيعات.
5. **Order.SellerId**: إسناد البيع التاريخي للبائع الأصلي (لا يُنقل عند إعادة تكليف). التقييمات تُحسب على SellerId للموظف المعروض.
6. **التعطيل**: `EndsAtUtc` يوقف الأهلية فورًا للمسارات الجديدة (دوام/GPS/قوائم). لا يمسح المبيعات التاريخية.
7. **حظر التطبيق** (`SalesEmployeeAppBlock`): يمنع تطبيق المبيعات (login/shift) فقط — **لا** يعطّل الجباية ولا لوحة الإدارة.
8. **Backfill**: لا تخمين تلقائي. حسابات Mandob بلا تكليف = سجل مراجعة. SellerId بلا تكليف يبقى في الحقائق التاريخية دون منحه أهلية قائمة.

## المشاركة
نفس الاستعلام عبر: SalesOverview، SalesEmployees، SalesFollowup (قائمة)، SalesEmployeeTracking، بوابة ingest تطبيق المبيعات.
