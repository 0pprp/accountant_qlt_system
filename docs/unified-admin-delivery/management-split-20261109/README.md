# فصل المدير المفوض وإدارة الفروع

تاريخ التصحيح: 2026-11-09. النطاق: فصل التنقل، تصحيح ربط التبويبات، توحيد غلاف الواجهة وشريط البحث، وفحص المتصفح. هذا ليس إعلان اكتمال نقل جميع وظائف تطبيقي Flutter.

## النتيجة

- «لوحة الإدارة» للإشراف والملخص والتقييمات وعمل المتابعين.
- «المدير المفوض» أب مستقل، ومسار دخوله `/management/delegate`.
- «إدارة الفروع» أب مستقل، ومسار دخوله `/management/branch`.
- «المبيعات» تبقى مستقلة.
- لكل تطبيق أسماء وترتيب تبويباته العشرة من المصدر. التبويب غير المنقول يعرض «غير متاح بعد» دون رابط أعمال؛ التبويب المنفذ بلا صلاحية يظهر بقفل، والنقر عليه يذهب إلى منع الوصول.
- صلاحيات الدخول من المورد، وليست من اسم الدور. لا صلاحيات جديدة ولا تعديل قوالب أدوار أو قاعدة بيانات.
- روابط الأوراق القديمة محفوظة بحراستها. وظائف المستخدمين العامة وتقييم موظفي المبيعات وسجل النشاط لم تُحذف، لكنها لا تُقدَّم بوصفها حسابات إدارة الفرع أو تقييمات المفوض أو سجل قرارات قانونية.

## المصدر والحدود

المصدر القديم تحت `C:/GitHub/SalesHaider-main/SalesHaider-main`، مراجعة ملفات فقط، دون تشغيل تطبيقاته حياً:

- الفرع: `branch_manager_application/lib/ui/home_shell.dart` و `lib/core/api.dart`.
- المفوض: `delegated_manager_application/lib/features/shell/presentation/home_shell.dart` و `home_tabs.dart`.
- مبيعات الفرع: `branch_manager_application/lib/ui/new_sales_page.dart`؛ قائمة جديدة مع مقروء/غير مقروء، وليست قائمة المبيعات العامة.
- استثناءات المفوض: `delegated_manager_application/lib/features/exceptions/data/exceptions_repository.dart`؛ المصدر يتضمن markRead/decision. الجديد يعرض SalesRequest exceptions بقرار محمي، لكنه لا يثبت مطابقة صندوق القراءة القديم بكامل تفاصيله.

## العقود المستخدمة

لا API جديد في هذا التصحيح. `GET /api/v1/admin/ManagementTasks` يرسل `branchId` و`inboxForMe=true` من مهامي. الخادم يقيد inbox بالحامل الحالي. فتح التفاصيل والإجراءات يبقى وفق عقود ManagementTasks السابقة.

الاستثناءات تستخدم عقود SalesRequests الحالية مع `tab=exceptions` وشرط `SalesRequest.TabExceptions`. قرار الاستثناء يحتاج صلاحيته المستقلة من الخلفية؛ لا منح قراءة بسبب امتلاك ExceptionDecide فقط. الروابط المقيدة لا تغير منطق الإسناد أو الحالة.

## التحقق

- Vitest: 85/85؛ بينها ستة اختبارات جديدة لاستقلال الآباء، منع الربط الخاطئ، عزل صلاحيات الدخول واستمرار حراسة المسارات القديمة.
- Vite production build ناجح.
- type-check غير ناجح: 22 تشخيصاً في Auth/CustomerSelect/ProductSelect/DelegateFollowup/FollowerOldCustomers/Notification/Order/Safe/Sale ووحدات Sales*. لا تشخيص في ملفات فصل التنقل الجديدة. لم يُثبت baseline مستقل لكل تشخيص، ولا يُدَّعى أن type-check نظيف.
- Browser: تسجيل دخول طبيعي، 360/768/1440، النقر والرجوع، التحقق من عنوان التطبيق وعدد التبويبات. لا صفحة JS error ولا API 5xx في الجولة. اختبارات الصلاحيات للحساب المحدود وحدوية في هذه الجولة، لا ادعاء تحقق حي جديد لها.
- المرور على أقسام المتابعين دون اختيار متابع يثبت فتح الشاشة وحالة الاختيار فقط؛ لا يثبت نتائج بيانات أو إجراءات لم تُنفذ. لا بيانات وهمية ولا mutations أعمال في الإنتاج.
- شريط البحث للزبائن والتسديدات: تحقق إضافي 360/768 بلا overflow أفقي للصفحة؛ الجداول تحتفظ بالتمرير الداخلي لعرض الأعمدة.
- الأدلة في `evidence/` و`mobile-evidence/`. المطابقة الحية الكاملة مع التطبيقين القديمين غير مثبتة.
