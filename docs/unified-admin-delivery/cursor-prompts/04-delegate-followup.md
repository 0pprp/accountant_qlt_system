### التفويض ونطاق البيانات
- تبويب جاهز بدون صلاحية يظهر بقفل ويصل إلى AccessDenied بلا تركيب الصفحة أو طلب بياناتها؛ غير المنفذ لا يُقدّم كأنه مجرد قفل صلاحية.
- صلاحية دخول التبويب والقراءة مستقلة عن التعديل والإجراءات. امتلاك Update وحده لا يمنح Read ضمنيًا. سجل dependency في محرر الصلاحيات دون توسيع صلاحيات خفي. الأب يُفتح إذا أمكن دخول أحد الأبناء؛ لا تضف صلاحية أب تجبر المستخدم على شراء حقين لنفس القراءة.
- استخدم evaluator الحالي وRolePermissions/UserPermissions/UserPermissionDenials، لا نظام صلاحيات موازٍ ولا `if role == Director` داخل الشاشات أو الخدمات. الاستثناءات الأمنية لحساب Admin الحالي تُحفظ.
- API يتحقق من الصلاحية، الفروع المسموحة، المورد وملكيته/تكليفه الحالي. `branchId` مرشح لا إثبات تفويض. غيابه يعني جميع الفروع المسموحة فقط عندما يدعم العقد التجميع. تحقّق من customer/order/list/follower/employee ID المستهدف ومنع IDOR وmass assignment.
- افصل الحقول المالية والمستندات والمواقع والتصدير عند اختلاف صلاحياتها؛ لا ترسل الحقل المحظور للعميل أصلًا، ولا تعرضه صفرًا. إجمالي وتصدير وعدّادات الاستعلام تستخدم النطاق نفسه.
- احفظ نظام refresh وإبطال الجلسات الحالي. عند تغيير الفرع/الحساب/الصلاحيات، ألغ الطلبات القديمة وامنع تطبيق الرد المتأخر. Query keys تشمل الجلسة/النطاق والفلاتر والصفحة، وenabled يشترط جاهزية التفويض.
