## الجواب المباشر

**نعم — نفس البزنس لوجيك التشغيلي للرحلات الحرجة**، منقول داخل نظام موحّد مع **تشديد أمني مقصود**.  
**لا — ليس اكتمالاً حرفياً 1:1 بلا فجوات**: توجد فجوات UI/منتج (P0) وفجوات إثبات قبول، وليست بديلاً وظيفياً مختلفاً بالاسم.

| السؤال | الجواب |
|---|---|
| هل أثر العمل متطابق؟ | نعم في البيع / الجباية / اللجنة / الفرع / المحتوى / الصلاحيات الثلاثية |
| هل التنفيذ مطابق حرفياً؟ | لا — API موحّد CQRS بدل عدة backends |
| هل جاهز للقول «مكتمل بلا نواقص»؟ | لا — P0 تكليف الموظفين + إعلانات موظف المبيعات |

## تشديدات مقصودة (ليست نقصاً)

1. **صلاحيات:** Read مستقل عن الكتابة؛ Deny صريح؛ لا bypass باسم واجهة.  
2. **جمهور المحتوى:** `ContentAppAudience` + `AudienceDenied` (تكليف المبيعات يسبق Mandob).  
3. **Tutorial:** allowlist YouTube/Vimeo فقط.  
4. **Realtime:** مجموعة Hub من هوية السيرفر لا من معرف يختاره العميل.  
5. **تحصيل:** `ClientPaymentId` + أقفال advisory؛ رفض دفع المندوب عند قفل قائمة المتابع.  
6. **زيارة الفرع:** لا تركيب أعمال ولا استعلامات قبل استيفاء الزيارة؛ حراسة سيرفر أيضاً.
